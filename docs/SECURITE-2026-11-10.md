# Correctif sécurité du 10/11/2026 — à appliquer côté Supabase

Le code de cette PR se déploie tout seul via Vercel. **Mais la faille principale
se corrige dans la base**, et ça, c'est à faire à la main (5 minutes).

> ✅ Rien n'est supprimé : aucune table, colonne, ligne ou policy.
> ✅ Le coach garde l'accès complet à tous les athlètes.

## La faille

Un athlète connecté pouvait, depuis la console de son navigateur, se donner le
rôle `coach` (la policy `profiles_update` ne limite pas les colonnes), puis lire
les données de tous les athlètes. Même chose à l'inscription, via les
métadonnées `role` du `signUp`.

## Étapes

1. **Sauvegarde** : Supabase → Database → Backups (vérifie qu'un backup récent
   existe). En plan gratuit : Table Editor → `profiles` → Export CSV, par sécurité.
2. **Appliquer la migration** : Supabase → SQL Editor → coller
   `supabase/migrations/20261110120000_securite_roles.sql` → Run.
   - Le premier résultat liste les comptes non-`client`. Normalement : toi seul.
     Un compte inattendu ? Ne le supprime pas, préviens-moi.
   - Le dernier résultat doit afficher 3 triggers `benfit_*`.
3. **Fermer l'inscription publique** (les comptes sont créés par le coach) :
   Supabase → Authentication → Sign In / Providers → décocher
   **« Allow new users to sign up »**. La création de client par le coach
   continue de marcher (elle passe par la clé serveur).
4. **Tester** (avec l'UUID d'un compte athlète de test, ou n'importe quel
   athlète : la transaction est annulée par `rollback`, rien n'est modifié) :
   - Dans Supabase → SQL Editor, simuler l'athlète :
     ```sql
     begin;
     set local role authenticated;
     select set_config('request.jwt.claims', '{"sub":"<uuid-athlete-test>","role":"authenticated"}', true);
     update public.profiles set role = 'coach' where id = '<uuid-athlete-test>';
     rollback;
     ```
     → doit échouer avec « Modification du rôle ou du coach non autorisée ».
   - Vérifier dans l'app que l'athlète peut toujours modifier son profil
     (nom, objectif, taille) dans Mensurations, et que toi tu peux toujours
     changer l'offre, archiver, écrire des post-it.

## Retour arrière

Le bas du fichier SQL contient les 3 `DROP TRIGGER` pour annuler. Ils ne
touchent à aucune donnée.
